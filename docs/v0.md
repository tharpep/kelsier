# v0 — the premise test

Shell + tmux config, no binary. This is here to answer one question: **does an
always-visible state line plus jump-to-blocked actually fix the sprawl?**

## What's in it

| Path | Role |
|---|---|
| `hooks/kel-hook.sh` | state adapter — one script, called by 5 Claude Code hooks |
| `bin/kel-status` | renders the `status-left` fleet line |
| `bin/kel-jump` | `prefix \`` → next `waiting` window, cycling |
| `tmux/kel.conf` | status line + the one keybind + `allow-passthrough on` |
| `install.sh` | symlinks, `~/.tmux.conf` wiring, `jq` merge into `~/.claude/settings.json` |

## Install

```bash
cd ~/code/kelsier && ./install.sh
tmux kill-server          # or: tmux source-file ~/.tmux.conf in a running server
```

Restart any Claude Code sessions that were already running so they pick up the
hooks.

## Use

Sessions are hand-made tmux windows. The **window name is the session name** and
drives everything.

```bash
tmux new-session -s work -n auth-fix -c ~/code/some-repo
claude
# new window for a parallel task:
#   prefix c, then: rename-window rate-limit  (prefix ,) and cd + claude
```

The status line shows `[kel] 0:auth-fix? 1:rate-limit* 2:docs!` —
`?` waiting on you, `*` working, `!` done, bare = idle.

`prefix \`` jumps to the next window that's `waiting`.

## State model

`~/.local/state/kel/<window-name>.state`, one line: `<state> <epoch>`.
Written atomically. `.stash/<session-id>` holds the pane id captured at
`SessionStart` for hooks that don't inherit `$TMUX_PANE`.

Events → states: `UserPromptSubmit`→working, `Notification`→waiting,
`Stop`→done, `SessionStart`→idle, `SessionEnd`→file removed.

## Pane resolution (the thing to verify)

The hook needs to know which tmux window a Claude session lives in. It tries,
in order:

1. `$TMUX_PANE` from the hook's environment
2. the pane stashed by this session's `SessionStart` hook
3. the single tmux pane whose `pane_current_path` equals the payload's `cwd`

**Unverified until a real authenticated session runs:** whether Claude Code
passes `$TMUX_PANE` / `$TMUX` through to hook subprocesses at all. Tiers 2 and 3
are the safety net. If `$TMUX` itself is stripped and there's more than one tmux
server running, resolution can fail — acceptable for v0, revisit if it bites.

## Live test (needs `claude` logged in)

```bash
tmux new-session -s t -n probe -c ~/code/kelsier
claude
# submit any prompt, then in another pane:
cat ~/.local/state/kel/probe.state      # -> working, then done
ls ~/.local/state/kel/.stash/           # -> one file if SessionStart got the pane
```

If `probe.state` tracks the session, v0 works. Then: run agents in 2–3 windows
for a few days and see if the status line + `prefix \`` actually change how it
feels. Success/failure signals are in `rollout.md`.

## Uninstall

```bash
# remove the source-file line from ~/.tmux.conf, then:
jq 'del(.hooks.SessionStart, .hooks.UserPromptSubmit, .hooks.Notification, .hooks.Stop, .hooks.SessionEnd)' \
  ~/.claude/settings.json | sponge ~/.claude/settings.json   # or a temp-file swap
rm ~/.local/bin/kel-status ~/.local/bin/kel-jump
rm -rf ~/.local/state/kel
```

(A `.kel-bak.<epoch>` copy of `settings.json` is written on every `install.sh` run.)
